# Архитектура продукта и репозитория

## Приоритеты продукта

1. Библиотека трёх независимых направлений — QA, AI и Tools — со статьями, схемами, таблицами и шпаргалками, прежде всего для телефона. AI включает личное обучение, игры и приложения, бытовую автоматизацию и будущие бизнес-проекты; он не ограничен тестированием.
2. Поисковый каталог QA-, AI- и инженерных инструментов.
3. Проверки знаний, упражнения и геймификация позднее.

## Границы репозитория

| Путь | Ответственность |
| --- | --- |
| `apps/web/` | Адаптивное веб-приложение и локальный просмотр |
| `apps/mobile/` | Будущее Android-приложение |
| `packages/content/` | Общие контракты контента и будущая загрузка |
| `packages/i18n/` | Общие тексты интерфейса и правила локализации |
| `qa/`, `ai/`, `tools/` | Основные заметки знаний и инструментов |
| `playbooks/`, `glossary/` | Практические ресурсы и определения |
| `inbox/` | Необработанные источники |
| `docs/` | Решения продукта и архитектуры |

Web и mobile остаются в одном репозитории с отдельными приложениями и общим контентом. Код представления разделяется только там, где технологии делают это практичным. Общий framework, workspace менеджера пакетов, backend и hosting-провайдер пока не выбраны.

## Языки

Английский и русский активны для интерфейса, заметок, схем, шпаргалок и документации читателя. Сохраняйте исходные названия и URL для атрибуции.

Русские файлы повторяют пути в `locales/ru/` с общими ID. Немецкий запланирован. Одно приложение обслуживает оба языка; предпочтение URL выше сохранённого. При отсутствии перевода явно показывается английский. Перед публикацией запускайте `python scripts/check_translations.py`.

## Разработка и поставка

Первая реализация — веб-приложение. Локальный просмотр позволяет проверять до GitHub. Размещённая версия даст доступ с телефона и компьютера без постоянно включённого компьютера разработки.

Android — будущая цель с тем же контентом. Статический web-reader запускается локально; Android пока заготовка. Офлайн-чтение, синхронизация, аутентификация и Google Play требуют отдельных решений.

## Представление контента

Сначала краткое изложение, затем подходящая схема или шпаргалка, далее подробности, практика, ограничения, связи и источники.

Используйте читаемый мобильный макет вместо огромных инфографик с постоянным zoom. По возможности сохраняйте схемы редактируемыми, а подписи переводимыми.
