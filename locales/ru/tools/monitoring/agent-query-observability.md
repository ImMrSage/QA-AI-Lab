# Наблюдаемость запросов к данным на естественном языке

## Кратко

Jefferies описывает диалогового помощника с поиском схемы, генерацией SQL и MCP-инструментами. Исполнитель применяет построчные права перед запросом. Отдельный renderer строит визуализации вместо выдумывания данных графика моделью. Контекст сессии и аудит помогают расследованию. Расширение AgentCore в этом рассказе — работа дорожной карты.

## Практическая цепочка QA-свидетельств

| Этап | Что предлагается сохранять |
| --- | --- |
| Запрос | Личность пользователя, смысл вопроса и correlation ID |
| Поиск | Версия схемы и значимые определения метрик |
| SQL-запрос | Сгенерированный запрос и действующая область прав |
| Выполнение | Временная метка источника, длительность, число строк и ошибки |
| Представление | Значения для renderer и итоговый ответ |

Для QA-dashboard независимо посчитайте известное число упавших тестов, спросите помощника и сравните фильтры, часовой пояс, дедупликацию и показанные значения. Повторите под ролью без доступа к части проектов. Проверьте, не сохраняют ли уточняющие вопросы старый проектный фильтр случайно.

## Ограничения

Синтаксически корректный SQL может отвечать не на тот вопрос. Проверка прав требует adversarial-тестов joins, подзапросов, агрегации и альтернативных инструментов; инструкции модели или фильтра контента недостаточно. Отдельный renderer не исправляет плохие результаты запроса. Защищайте чувствительное содержимое трасс и определяйте срок хранения.

Статья — архитектурный кейс, а не подробная реализация наблюдаемости или измерение точности. Бесшовный доступ и эффективность независимо не доказаны. Из технического примера не выводятся финансовые рекомендации, инфраструктура не развёртывалась.
