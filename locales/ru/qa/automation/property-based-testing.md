# Тестирование на основе свойств с Hypothesis

## Кратко

Статья объясняет генерацию примеров стратегиями, проверку свойств, уменьшение неудачных случаев до простых контрпримеров и сохранение регрессионных примеров. Рассматриваются зависимые входы, модели состояний, CI и изоляция между сгенерированными примерами. Сложнее всего придумать содержательное свойство и допустимую область входов, а не просто увеличить число примеров.

## Матрица проектирования свойств

| Свойство | Авторский пример лаборатории |
| --- | --- |
| Обратимость | Декодирование закодированного поддерживаемого значения без потерь |
| Инвариант | Количество в корзине неотрицательно после допустимых операций |
| Сравнение с эталоном | Оптимизированный расчёт совпадает с доверенным базовым |
| Метаморфное отношение | Перестановка входов не меняет сумму, не зависящую от порядка |
| Идемпотентность | Двойная нормализация равна однократной |

## Практика

Начните с одного парсера или нормализатора. Определите допустимые входы, запишите свойство, изучите минимизированный сбой и сохраните подтверждённый дефект как регрессию. В stateful-тестах после каждой операции проверяйте ожидаемые записи и отсутствие неожиданных.

## Ограничения и уточнения

Инвариант корзины в источнике проверяет ожидаемые элементы, но может пропустить лишние или неудачное удаление. Поиск без учёта регистра и преобразование без потерь являются свойствами только при соответствующем контракте. Генерируемые тесты дополняют тесты на примерах и не доказывают корректность. Интеграционные функции тоже можно проверять свойствами при подходящей изоляции; категоричный отказ источника слишком широк. Исследовательские метрики, настройки по умолчанию и фрагменты кода независимо не воспроизводились. Успешный запуск не гарантирует посещения каждой границы.
