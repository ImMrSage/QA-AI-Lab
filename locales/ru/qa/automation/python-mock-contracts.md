# Моки Python: контракт, результат и жизненный цикл

Подмена полезна, когда тест изолирует внешнюю зависимость. Она не должна принимать вызовы, которые реальная зависимость отвергнет. Проверяйте результат приложения и отдельно — соответствие подмены контракту.

## Семь проверок подмены

| Риск | Решение |
| --- | --- |
| Изменилась сигнатура | autospec для проверки аргументов |
| Патч не перехватил вызов | Подменить имя, которое код разрешает при вызове |
| Mock попал в условие | Задать конкретные bool, числа и структуры ответа |
| Патч пережил тест | Контекстный менеджер либо гарантированный cleanup |
| Проверяются только вызовы | Добавить ожидаемый результат и побочные эффекты |
| Аргумент изменился после вызова | Снять копию или проверить внутри side_effect |
| Async заменён обычным объектом | AsyncMock и проверка await |

`spec` ограничивает доступные атрибуты, `spec_set` также запрещает добавлять неизвестные; `autospec` проверяет сигнатуры. Для строгой комбинации используйте `create_autospec(..., spec_set=True)`. Autospec сам по себе не гарантирует тип возвращаемого значения и не включает автоматически запрет присваивания новых атрибутов.

При `from gateway import send` вызов ищет `send` в импортирующем модуле. При `import gateway` он ищет `gateway.send`. Проверяйте реальный способ импорта. Динамические атрибуты и дескрипторы требуют внимания при autospec; узкий интерфейс часто проще большого объекта.

## Авторский пример

```python
from unittest.mock import create_autospec

def save_note(text, *, operation_id):
    return {"id": operation_id, "text": text}

save = create_autospec(save_note, spec_set=True)
save.return_value = {"id": "note-1", "text": "QA"}
result = save("QA", operation_id="note-1")
assert result["text"] == "QA"
try:
    save("QA")
except TypeError:
    pass
else:
    raise AssertionError("Missing operation_id was accepted")
```

Пример проверяет механизм подмены, не настоящее сохранение. Для теста приложения вызов должен идти через код приложения; ожидаемый эффект проверяется независимо. Этот учебный фрагмент выполнен локально, внешние сервисы не вызываются.

Fake с настоящим состоянием удобен для бизнес-результатов, но тоже может устареть. Сверяйте общий набор контрактных сценариев с fake и реальной тестовой зависимостью. Для изменяемых аргументов копирование может сломать проверку идентичности — выбирайте наблюдение по требованию.
