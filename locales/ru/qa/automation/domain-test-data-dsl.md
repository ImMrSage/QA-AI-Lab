# Предметный язык данных интеграционных тестов

## Кратко

HFLabs описывает добавление Groovy DSL поверх существующего интеграционного фреймворка на DBUnit. Табличные фикстуры раскрывали детали хранения и осложняли ревью и слияния. Новый слой выражает клиентов, связи и ожидаемые изменения в терминах предметной области, сохраняя движок выполнения и артефакты сравнения БД.

## Как это работает

| Слой | Ответственность |
| --- | --- |
| Сценарий | Бизнес-сущности и значимые переопределения |
| Значения по умолчанию и отображения | Преобразование предметных атрибутов в данные реализации |
| Существующий движок | Подготовка данных, выполнение, сравнение и очистка |
| Обходной путь | Описание необычных таблиц вне покрытия DSL |

Источник также описывает переиспользование контекста начального состояния при построении ожидаемого. Число сценариев показывает внедрение, а не независимо измеренное улучшение качества.

## Практическое применение в QA

Проведите пилот на одном часто меняющемся семействе фикстур. Сравните понятность ревью, стоимость миграции и диагностику с прежним форматом. Авторский пример лаборатории: клиент с двумя адресами; задайте только изменяемый адрес и проверьте сохранность второго.

Ожидаемые результаты должны быть достаточно независимы, чтобы выявлять ошибки реализации. Проверяйте сам слой отображения: неверное общее значение по умолчанию может одновременно испортить множество сценариев. Осознанно версионируйте значения по умолчанию и делайте важные предусловия видимыми на ревью.

## Ограничения

Это Groovy, а не независимый от языка рецепт. Динамическому поведению нужны понятные ошибки и документация. Большие сценарии остаются большими; прямое обращение к таблицам может размывать абстракцию. Поддержка IDE, описанная как будущая работа, не считается готовой возможностью. Код фреймворка не запускался.
