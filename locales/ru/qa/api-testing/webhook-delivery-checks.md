# Вебхуки: события и проверки доставки

Вебхук — HTTP-уведомление от сервиса на настроенный endpoint при наступлении события. При polling получатель периодически спрашивает об изменениях; при вебхуке отправитель инициирует запрос. Вебхук может быть частью API, а не его противоположностью. В уведомлении могут быть данные события либо идентификатор для последующего API-чтения.

## Матрица проверок

| Сценарий | Проверяемый результат |
| --- | --- |
| Событие произошло | Верный тип, объект и полезная нагрузка |
| Повторная доставка | Нет повторного бизнес-действия |
| События пришли не по порядку | Состояние не откатывается ошибочно |
| Endpoint недоступен | Поведение повторов и восстановления соответствует отправителю |
| Подпись неверна | Нет обработки недоверенного события |
| HTTP-ответ успешен | Событие принято надёжно; обработка наблюдаема отдельно |

Повторы зависят от провайдера: Stripe описывает автоматические повторные попытки, GitHub — восстановление пропущенных доставок. Не предполагайте ни доставку ровно один раз, ни обязательную потерю при первом сбое. Идентификатор события или доставки полезен для дедупликации; его смысл определяется контрактом.

## Учебный пример

При регистрации участника получатель ставит отправку приветственного письма в очередь. Проверьте нормальное событие, дубль и сбой worker после HTTP-подтверждения. Ожидание: одно письмо, восстановимая задача и запись о результате. Подтверждение до надёжного сохранения может потерять работу; повтор после сбоя может продублировать её.

Проверяйте HTTPS и подпись по документации отправителя, включая исходные байты тела, если это требуется алгоритмом. CORS не аутентифицирует межсерверный запрос. Учебный PHP-фрагмент исходной статьи не является готовым защищённым обработчиком; формат JSON и form-data нужно разбирать по Content-Type.
