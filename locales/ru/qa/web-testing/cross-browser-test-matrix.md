# Кроссбраузерность: матрица сред и проверок

Совместимость проверяют для сочетания браузера, версии, ОС и способа открытия приложения. Различия движков, системного отображения и встроенных WebView остаются значимыми. Выбирайте среды по аналитике продукта и последствиям отказа, а не по глобальному рейтингу браузеров.

## Матрица проверки — рабочий шаблон

| Сигнал продукта | Добавить в матрицу | Проверить результат |
| --- | --- | --- |
| Критический пользовательский путь | Основные поддерживаемые браузеры | Вход, основное действие, сохранение, выход |
| Пользователи с отложенными обновлениями | Минимальную поддерживаемую версию | Работу ключевых возможностей и fallback |
| Жалобы на расположение элементов | Реальную ОС и масштаб пользователя | Popup, sticky, таблицы, обрезание текста |
| Переходы из встроенного приложения | Конкретное приложение и устройство | Сессию, редиректы, разрешения, возврат |
| Интерактивная графика или мультимедиа | Целевое устройство | Чёткость, управление, обработку отказа |

Это авторский шаблон планирования, а не перечень обязательных комбинаций. Для каждой строки назначьте владельца, периодичность и критический сценарий. Не перемножайте все параметры без оценки риска.

## Как экономить проверки

1. Соберите распределение сред среди активных пользователей и среди неуспешных критических действий. Малый сегмент может иметь высокий риск.
2. Разделите обязательную поддержку, дополнительные проверки и неподдерживаемые среды. Укажите версию и дату пересмотра политики.
3. На изменениях запускайте короткие автоматические проверки критических путей; перед выпуском добавляйте целевые реальные среды.
4. Для визуальных сравнений используйте эталон конкретной среды. Разница пикселей между ОС сама по себе не доказывает дефект.
5. После найденного бага добавляйте воспроизводящий сценарий и проверяйте, нужен ли новый сегмент матрицы.

Playwright позволяет разделить Chromium, Firefox и WebKit на проекты и запускать Chrome/Edge через каналы. Его WebKit не является установленным Safari. Эмуляция мобильных параметров полезна для раннего отбора проблем, но не подтверждает работу внутри целевого приложения на телефоне.

## Совместимость возможностей

Baseline помогает оценить доступность веб-возможностей. Он не сертифицирует весь продукт: старые версии и встроенные среды требуют отдельных решений. Проверяйте необходимые API и понятное поведение при их отсутствии.

Не превращайте отдельный браузерный баг в вечное правило. Для fullscreen, аудио, sticky и сочетаний CSS сохраняйте минимальный пример и точную версию. Для WebView записывайте настройки хоста; нельзя заранее объявлять API недоступным во всех WKWebView.

## Карточка дефекта

- Сборка приложения, URL, точные шаги и ожидаемый результат.
- Браузер и версия; ОС и версия; для WebView — приложение-хост и его версия.
- Viewport, browser zoom, системный масштаб и DPR, если дефект визуальный.
- Screenshot или видео; ошибки консоли и сеть без секретов.
- В каких средах воспроизводится и где проходит; влияние на пользовательское действие.
