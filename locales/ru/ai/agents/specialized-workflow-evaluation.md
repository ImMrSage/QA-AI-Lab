# Оценка специализированных процессов агентов

## Кратко

AWS и NVIDIA демонстрируют цепочку поставок, соединяя Amazon Quick с процессом NeMo Agent Toolkit через AgentCore. Отдельные инструменты изучают задержанные заказы, запасы, влияние на клиентов, политики и логистику до ранжирования мер. Рекомендацию сопровождают структурированные свидетельства, время и результаты оценки. Примеры инструментов используют CSV; production-интеграции ещё нужно реализовать.

## Границы проверки

| Граница | Предлагаемая QA-проверка |
| --- | --- |
| Маршрутизация чата | Отличать вопрос о dashboard от запроса процесса |
| Вход инструмента | Отклонять неизвестные ID поставщиков и неверные параметры |
| Решение по политике | Требовать нужное одобрение предлагаемого действия |
| Свидетельства | Связывать каждую рекомендацию с актуальными записями |
| Частичный сбой | Показывать отсутствие данных запасов или политик, не выдумывая их |
| Фактическое действие | Разделять рекомендацию изменения и выполнение |

## Практика

Примените подход к триажу инцидентов: соберите сведения развёртываний, ошибок и зависимостей, предложите шаги и сохраните причину каждого. Проверяйте инструменты отдельно, затем оркестрацию, затем полный пользовательский путь. Backend-оценщик не доказывает правильность выбора действия чатом.

## Ограничения и уточнения

Локальный оценочный стенд не проверяет полный диалог Quick. Пример задержки — один демонстрационный запуск, а не измерение ёмкости. Каталог клонирования и последующий `cd` различаются; проверьте настройку до запуска. Ссылки конфигурации тоже требуют сверки с зарегистрированными именами функций.

Пример явно использует `AuthorizerType=NONE`; заголовок-заглушка не является аутентификацией. Production-адаптации нужны принудительная проверка личности и авторизация. Разрешение расследования не разрешает последующие записи ERP. Развёртывание, запуск примера и аудит репозитория не выполнялись.
