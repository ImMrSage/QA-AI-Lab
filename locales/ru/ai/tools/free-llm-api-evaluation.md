# Бесплатные LLM API: условия и проверка пригодности

Бесплатный тариф, пробный баланс и бесплатный маршрут внутри платного сервиса решают разные задачи. Перед подключением оцените качество ответа, предсказуемость маршрута и полную стоимость рабочего процесса.

## Шесть вариантов из обзора

Ниже — наблюдения Ungated в статье от 14 сентября 2026 года. Мы эти API не тестировали; бонусы и доступность требуют повторной проверки.

| Сервис | Формат доступа по обзору | Ограничение наблюдений |
| --- | --- | --- |
| Token Harbor | Бесплатные модели | Объём квоты не установлен |
| WoAiToken | Бесплатные пулы; $5 бонус | Модель меняется; встречались ошибки |
| Unikey | 5 000 credits | Пробный баланс; каталог не гарантирует ответ |
| God Router | Отдельные бесплатные маршруты | Для одного маршрута сервер сообщил 8 RPM |
| ABCRelay | $2 бонус | Пробный баланс; часть маршрутов не работала |
| Z.ai | Бесплатные Flash-модели | Отдельные модели и лимиты проверять отдельно |

## Проверенные условия документации

На 3 октября 2026 года Token Harbor публикует для бесплатного аккаунта 60 запросов/мин и 1 800/час, для IP — 100/мин и 3 000/час; ключи и модели разделяют лимит аккаунта. При превышении описаны HTTP 429 и Retry-After. Это лимиты частоты, а не размер бесплатного токенного бюджета.

В тарифной таблице Z.ai GLM-4.5-Flash и GLM-4.7-Flash отмечены как бесплатные. FlashX — отдельные платные варианты. Бесплатность модели не означает бесплатность всех встроенных инструментов.

## Протокол выбора для QA Lab

Это предлагаемый эксперимент, не внедрённая интеграция.

1. Подготовить 20 публичных или синтетических примеров классификации ссылок с ожидаемыми категориями и сложными пограничными случаями.
2. Проверить ответ по схеме: допустимая категория, корректный JSON, обоснование, возможность отказаться при недостатке данных.
3. Записать дату, маршрут, заявленный идентификатор модели, задержку, размер ответа, ошибки и баланс до/после. Идентификатор провайдера сам по себе не подтверждает происхождение модели.
4. Ограничить параллелизм, таймаут и число повторов. Не повторять ошибки оплаты или неверной модели вслепую; соблюдать Retry-After при ограничении частоты.
5. Сравнить стоимость одного принятого результата с текущим процессом, включая ручные исправления и повторы. HTTP 200 с пустым или неверным ответом не считать успехом.
6. Оставить основную обработку и публикацию за текущим workflow до успешного пилота. Для внешнего сервиса использовать отдельный ключ с лимитом расходов и заранее проверить правила хранения данных.

Для сортировки допустим меняющийся пул только после проверки качества на наших категориях. Для повторяемых сравнений предпочтительнее фиксированный маршрут. Короткий нагрузочный прогон показывает наблюдаемую пропускную способность, а не гарантированный предел или SLA.
